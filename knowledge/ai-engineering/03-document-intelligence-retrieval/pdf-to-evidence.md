# From PDF to Evidence

## Intuition

A PDF is closer to a set of instructions for painting pages than to a database of paragraphs. It may say “draw these glyphs at these coordinates,” while the reader infers heading, paragraph, column, and footnote.

## Precision

PDFs can contain text objects, font mappings, vector graphics, raster images, annotations, forms, attachments, layers, signatures, and scripts. Visual order and internal object order may disagree. Some apparent text is only pixels. Some selectable characters use broken encodings.

## Document classes

- **Born-digital:** text and layout objects were generated by software.
- **Scanned:** pages are images and require OCR for textual access.
- **Hybrid:** selectable text and images coexist, sometimes with an OCR layer beneath a scan.
- **Adversarial or malformed:** unexpected structures, huge resources, embedded content, corruption, or deceptive layers.

Classification should happen per page when formats are mixed.

## Follow one contract

Suppose the question is: “What is the termination notice period?”

1. File validation confirms a permitted PDF and records checksum/source.
2. Parser extracts page objects or renders the page.
3. OCR handles scanned regions.
4. Layout analysis identifies the clause, heading, footnote, and reading order.
5. Structured representation records text plus page and bounding box.
6. Chunking keeps the clause with its heading and exceptions.
7. Retrieval returns the relevant clause.
8. Reranking separates it from similar renewal language.
9. Context assembly preserves source and neighbouring exception.
10. The answer cites the page and clause.

If step 4 joins two columns incorrectly, later model quality cannot restore the original clause reliably.

## Canonical intermediate representation

Avoid treating Markdown as the only source of truth. Preserve a structured document model with:

- document/page/element IDs;
- element type;
- text or asset reference;
- page and bounding region;
- hierarchy and reading order;
- table cells and spans;
- parser/OCR model and version;
- confidence where meaningful;
- source checksum and ingestion time.

Markdown is an excellent view; it is a lossy interchange for some layouts.

## Security boundary

Before parsing:

- authenticate source and owner;
- enforce size/page/time limits;
- validate content rather than extension;
- isolate parser execution;
- reject or strip active content according to policy;
- scan for malware;
- record provenance;
- avoid logging document contents indiscriminately.

Parsers process hostile files and deserve the same isolation as other untrusted-input systems.

## Cross-domain transfer

- **AI:** ingestion quality bounds grounding quality.
- **Full stack:** file uploads require authorization, object storage, jobs, status, retries, and deletion.
- **Games:** asset importers similarly convert flexible source formats into canonical engine representations; importer versioning affects reproducibility.
- **Research:** document benchmarks may not represent legal, multilingual, handwritten, historical, or domain-specific material.

## Misconception

“The PDF opens correctly, therefore its text is extractable correctly.” Visual rendering success proves little about semantic extraction.

## Senior questions

- Can every answer be traced to immutable source coordinates?
- Can a document be reprocessed without losing the previous index?
- How are parser upgrades compared and rolled back?
- What is deleted when the source owner revokes access?
