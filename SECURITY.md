# Security Policy

## Scope

This repository is primarily educational documentation, with small Python and C++ examples and repository-validation scripts. Security reports may concern executable examples, automation workflows, dependency instructions, credential exposure, unsafe commands, or advice that could create a material production vulnerability.

## Reporting

Do not place credentials, personal data, private exploit details, or sensitive system information in a public issue.

For non-sensitive documentation corrections, open a normal GitHub issue. For a vulnerability that should remain private, use GitHub's private vulnerability reporting feature when it is available on the repository. If that channel is unavailable, open a minimal issue requesting a private contact channel without disclosing the vulnerability.

## Expectations

Reports should identify the affected file or workflow, realistic impact, reproduction conditions, and a safe remediation direction. Educational examples are not production-ready unless explicitly stated, but misleading security boundaries are still treated as defects.

No page, framework, benchmark result, control checklist, or passing validator constitutes a guarantee of security, safety, privacy, or regulatory compliance.
